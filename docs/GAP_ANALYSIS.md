# 现状 vs 最终目标：差距分析

最终目标（原始需求）：
> 车联网车载感知场景，基于 YOLO+ByteTrack 对**视频中的车辆、行人**做持续跟踪；实现**目标 ID 维持、轨迹生成**；
> **对比不同跟踪策略**，分析 **ID 切换率、跟踪速度**；**输出目标轨迹**，为车联网**运动目标状态感知**提供信息。
> 数据集：BDD100K、MOT17（交通子集）。

当前已跑通：BDD100K 1 条序列（203 帧 / 5 fps / 1280×720 / 63 条 GT 轨迹），5 种跟踪策略对比。

## 2. 当前最大瓶颈：检测（不是跟踪）

同一份检测下的分类别看（`out/<seq>_final.jsonl` vs GT）：

| 类别 | GT 框 | 检出 TP | 召回 | 精确 | IDSW | GT 轨迹 | 产出 ID 数 |
|---|---|---|---|---|---|---|---|
| car | 7800 | 4771 | **61%** | 85% | 89 | 54 | 42 |
| **person** | 631 | 163 | **26%** | 84% | 2 | 7 | 5 |
| **truck** | 288 | 1 | **0%** | 0% | 0 | 2 | 6 |
| bus | 0（本段无） | 0 | — | — | — | 0 | 2 |

- 整体：召回 53%、精确 84%、MOTA 0.426、IDF1 0.596
- **FN（5382）是 TP（约 4900）的 1.1 倍** → MOTA 上不去的主因是漏检，不是 ID 切换
- **卡车召回 0% + 274 个 truck FP** → 典型的 COCO ↔ BDD 类别定义不一致（BDD 把厢式货车标 car，YOLO 标 truck），必须做类别映射/微调
- 行人 26% → 直接违背"对车辆、行人做持续跟踪"的目标

**结论：现在的"策略对比"其实是在比"谁更能容忍漏检"，不是在比关联算法。**

## 3. 三个必须写进报告的口径警告

1. **ID 切换率 1.84% 偏乐观**：IDSW 只在"匹配上的帧"之间统计，漏检越多、分母越小、切换机会越少。低召回会**系统性美化** ID 指标。
2. **单视频结论不可外推**：63 条轨迹、5 fps、单场景、单光照；IDSW 的方差很大。
3. **5 fps 源本身不真实**：真实车载/路侧视频是 10~30 fps，帧间位移小、关联容易，因此 BDD 上的 IDSW 天然偏高，不能与其他论文数字直接比。
