## 2. 结论：适合什么 / 不适合什么

### ✅ 不可替代的价值

1. **遮挡下的 ID 维持试金石**：vis<0.3 的框占 17~52%，45% 的轨迹长于 120 帧 → 长时遮挡后重连（ReID/CMC/轨迹插值）的收益在这里才测得出来。
2. **高帧率连续视频对照**：主流 30 fps，与 BDD 跟踪帧的 5 fps 形成天然对照，可量化"帧率 → IoU 关联难度 → IDSW"的因果链。
3. **分辨率与帧率双跨度**：1080p 与 480p、14/25/30 fps 混杂 → 分辨率消融、帧率敏感性分析的现成素材。
4. **社区标准**：TrackEval/MOTChallenge 协议成熟，HOTA/IDF1 可与论文直接对标。
5. **GT 质量高**：逐帧人工框 + 连续 `vis` 分数 + 忽略区标注。

### ❌ 硬性局限（必须写进报告）

1. **只有行人一类**（`class=1`；2/7/8/12 全是需忽略类）。车辆、骑行者、卡车全无 → **车辆相关结论一律以 BDD100K 为准**，MOT17 只能承担"行人 ID 维持"的结论。
2. **只有 7 条 train 序列 / 5 316 帧**：单序列 IDSW 波动即可翻转结论 → 必须 **per-sequence 报告 + 宏平均与加权平均并列**，不能只给一个总数。
3. **test 7 条无 GT**：想用只能提交 MOTChallenge 官方服务器（周期以天计）→ 本课题不提交，全部结论基于 train 7 条 + 自我划分调参/评测。
4. **三个检测器变体**（DPM/FRCNN/SDP，`det/det.txt` 不同、GT 相同）→ 目录上是 21 条。我们用自有 YOLO 检测，**只在 7 条基序列上评测一次**，并在报告说明偏离官方协议的理由（否则会出现三份重复结果）。
5. **场景单一**：欧洲城市步行街/广场，无夜间、无雨雪、无高速 → 不能做天气/时段分层（这一层只能靠 BDD）。
6. **密度极度不均**：8.3~45.3 人/帧（5.5 倍），且 MOT17-04 一条就占全部框的 **42%** → 聚合 MOTA/IDF1 实际主要反映 04 的表现，必须说明加权口径。
7. **帧率不齐**：05 是 14 fps / 640×480，13 是 25 fps，其余 30 fps → 做帧率分析时是优点，做平均时是噪声源。

## 3. 本课题中的使用协议

| 项 | 决定 |
|---|---|
| 角色 | **行人 ID 维持压力测试集 + 高帧率对照集**，非主数据集 |
| 评测序列 | 7 条 train 基序列（02/04/05/09/10/11/13），忽略 DPM/FRCNN/SDP 变体 |
| 划分 | 调参：02/05/09；评测：04/10/11/13（或 2 折交叉，报告两折均值±标准差） |
| 检测 | 自有 YOLO（不用 `det.txt`），batch=1 流式；输入 640/960 对比 |
| GT 处理 | 仅 `class=1`；`class∈{2,7,8,12}` 与 `conf=0` 按 ignore；忽略区参考官方 ROI |
| 指标 | HOTA/DetA/AssA/MOTA/IDF1/IDSW/Frag/MT/ML，**逐序列 + 宏平均 + 加权平均** |
| 速度 | 5316 帧全量跑（3050 上约 2~5 min），报 FPS 与 P95 延迟 |
| 不提交 | test 服务器（除非后续要打榜） |

## 4. 关键风险：参数跨数据集迁移

MOT17 是**行人 + 30 fps + 低速**，BDD 是**车辆 + 5 fps + 高速运动相机**。
在 MOT17 上调好的 `track_buffer / match_thresh / Kalman 噪声` 直接搬到 BDD 会明显退化（5 fps 帧间位移大、IoU 重叠小）。

→ 处理方式：
1. **两套数据集分别调参、分别报告**，不共用一套超参。
2. 额外做一个**参数迁移敏感性实验**：把 A 集最优参数用于 B 集，量化 IDSW 退化幅度 —— 这既解释了差异来源，也是报告里的加分项（"帧率/类别变化对跟踪器超参的鲁棒性"）。
